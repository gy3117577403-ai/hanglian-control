# 安全策略

## 密钥管理规则

- 仓库只保存示例配置文件，不保存真实密钥。
- 本机配置使用 `.env.local`，该文件必须被 `.gitignore` 忽略。
- 数据库连接串、企业微信授权信息、对象存储凭据和语音平台凭据不得出现在代码、文档和提交历史中。
- 如果后续需要 CI/CD 使用敏感配置，应通过 GitHub Secrets 或部署平台环境变量注入。
- 发现疑似密钥时，只记录文件路径和风险类型，不打印密钥内容。

## 上传资料规则

- 真实客户资料、真实 PDF、真实 SOP、真实图纸和真实成品图片不得提交到 GitHub。
- `apps/api/storage/uploads` 仅用于本地开发演示。
- 本地生成的资料 metadata 和审计记录不得提交。
- 需要保留空目录时，只提交 `.gitkeep`。

## 数据库连接规则

- 默认数据源保持 Mock。
- 未进入数据库验证阶段前，不连接 Sealos PostgreSQL。
- 数据库测试库连接串只允许保存在本机或受控环境变量中。
- 未经明确授权，不执行迁移、db push、seed 或任何写库操作。
- 生产数据库操作必须先有备份、回滚方案和测试库验证记录。

## 企业微信微盘授权规则

- 当前阶段不接真实企业微信微盘。
- 企业微信授权信息不得写入代码仓库。
- 后续接入时应使用专门的授权配置、最小权限账号和独立审计记录。
- 文件同步应先在测试目录验证，避免误读或误写真实资料。

## GitHub 提交前检查规则

提交前至少执行：

```bash
npm run security:check
npm run build
npm run check
```

检查重点：

- `.env.local` 是否未被 Git 跟踪。
- 是否存在真实连接串或账号凭据。
- 是否存在真实客户资料和真实图纸。
- 本地上传目录和 metadata 是否未被 Git 跟踪。
- 构建是否通过。

## 生产环境部署前检查规则

- 确认运行环境变量由部署平台注入。
- 确认数据库目标环境正确。
- 确认写库和危险操作开关保持关闭，除非有明确审批。
- 确认日志不会输出密钥、连接串和客户隐私资料。
- 确认上传资料存储、访问权限和备份策略已配置。
- 确认回滚方案和应急联系人已准备。
