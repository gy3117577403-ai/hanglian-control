# V0.2 开发说明

## 阶段目标

V0.2 将平板端从“纯本地 Mock 展示”升级为“优先通过后端 Mock API 获取数据”的真实数据流原型。系统仍不连接真实 Sealos PostgreSQL、企业微信微盘或语音识别平台。

## 已实现范围

- 页面加载时调用 `GET /api/health` 检查 API 状态。
- API 在线时调用 `GET /api/production-plans?scope=today` 获取今日计划。
- 切换本周计划时调用 `GET /api/production-plans?scope=week`。
- 点击计划任务时调用 `GET /api/production-plans/:id` 获取计划详情和产品资料包。
- 搜索时调用 `GET /api/search?q=关键词&planId=当前计划`。
- 组长确认时调用 `POST /api/production-plans/:id/confirm`。
- 异常反馈时调用 `POST /api/feedback`，并通过 `GET /api/feedback?planId=...` 读取当前计划反馈记录。
- 后端不可用时自动切换本地 Mock fallback，并显示“离线演示模式”。

## 前端数据流

`TabletDashboard.vue` 挂载后调用 Pinia store 的 `initialize()`：

1. `checkApiHealth()` 检测后端。
2. `loadPlans(scope)` 拉取今日或本周计划。
3. `selectPlan(planId)` 拉取计划详情与反馈记录。
4. 用户操作触发搜索、确认、反馈等 API 调用。
5. API 失败时使用 `apps/tablet/src/mock/production-data.ts` 本地数据兜底。

## 后端数据流

后端 Mock 数据集中在 `apps/api/src/mock/production.mock.ts`。各模块 service 直接读取或修改内存数组：

- `production-plans`：计划列表、详情、确认状态。
- `search`：产品资料包字段搜索。
- `feedback`：异常反馈写入内存记录。
- `health`：API 健康状态。

## 持久化

当前仅前端保存少量非敏感偏好到 `localStorage`：

- 最近查询记录
- 当前计划范围
- 当前选中的计划 ID
- 当前前段/后段切换状态

后端数据为内存 Mock，服务重启后恢复初始数据。
