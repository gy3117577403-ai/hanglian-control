# V0.3 开发说明

## 阶段目标

V0.3 在不接真实数据库的前提下，把后端 Mock 数据层整理成“种子数据 + Mock Store + Repository + Service”的结构，并在前端加入开工资料完整性检查与版本状态管控展示。

## 后端 Repository 结构

- `apps/api/src/mock/seed-v0.3.ts`：集中维护客户、产品、生产计划、前段参数、后段资料包、资料文件、查询记录、确认记录和异常反馈种子数据。
- `apps/api/src/mock/mock-store.ts`：把 normalized seed 转换成 V0.2 兼容响应，并作为内存 Mock Store。
- `apps/api/src/repositories/production-plan.repository.ts`：生产计划列表、详情、确认和 readiness 读取。
- `apps/api/src/repositories/product.repository.ts`：产品资料包查询。
- `apps/api/src/repositories/search.repository.ts`：跨计划和当前计划优先搜索。
- `apps/api/src/repositories/feedback.repository.ts`：异常反馈内存写入和查询。

Controller 只处理 HTTP，Service 只协调业务，Repository 负责读写 Mock Store。后续替换 Prisma Repository 时，Controller 和前端接口不需要大改。

## 资料完整性检查规则

`evaluatePlanReadiness(planId)` 会生成：

- `readinessStatus`：`ready`、`need_review`、`blocked`
- `score`：完整性评分
- `summary`：平板端状态摘要
- `checkItems`：开工资料检查项
- `versionAlerts`：版本提醒和红线

前段检查 PDF 图纸、裁线长度、剥皮长度、端子型号、拉力标准、压接高度、前段参数版本和前段必需资料。后段检查连接器型号、装配说明书、插接孔位图、SOP、成品细节图、后段资料版本和后段必需资料。通用计划同时检查前段和后段。

## 版本状态规则

资料文件统一使用：

- `effective`：当前有效
- `pending_review`：待确认
- `expired`：已失效
- `missing`：缺失
- `inconsistent`：不一致

`pending_review` 生成黄色提醒；`expired`、`missing`、`inconsistent` 生成红色提醒并使开工状态进入阻塞或复核状态。

## 前端新增展示

- `services/api.ts` 增加 `getPlanReadiness(planId)`。
- Pinia store 增加 `readiness` 和 `readinessLoading`。
- 右侧资料区新增“开工资料检查”卡片。
- 版本提示优先使用 readiness 的版本提醒，分为绿色正常、黄色待确认、红色红线。
- 后端不可用时，本地 fallback 会计算基础 readiness。

## 后续接 Sealos 改造点

- 将 `mock-store.ts` 替换为 Prisma Repository。
- 将 `seed-v0.3.ts` 转为 Prisma seed 脚本。
- 将 readiness 规则保留在 service/utils 层，数据源改为 PostgreSQL。
- 为资料文件接入企业微信微盘授权、文件版本、checksum 和预览 URL。
- 为查询日志、确认记录、反馈记录接入真实持久化和审计。
