# V0.4 开发说明

## 阶段目标

V0.4 做真实数据库接入前准备，不连接 Sealos PostgreSQL，不执行迁移，不执行 `db push`。本阶段把 V0.3 的 Mock Repository 整理为可切换数据源架构，为后续 Prisma Repository 替换做铺垫。

## 为什么暂不接真实 Sealos

- 当前仍在原型阶段，需要先稳定 API 契约和资料检查规则。
- 真实数据库涉及账号、网络、权限、备份、迁移策略和回滚方案。
- 在没有测试库验证前，不应直接对生产库执行迁移或写入。

## Repository 接口设计

后端 service 通过统一接口访问数据：

- `ProductionPlanRepositoryInterface`
- `ProductRepositoryInterface`
- `DocumentRepositoryInterface`
- `SearchRepositoryInterface`
- `FeedbackRepositoryInterface`

Controller 不直接操作 Mock 数据；Service 不直接依赖 Mock Store。后续切换数据源时，前端和 Controller 不需要大改。

## Mock Repository 与 Prisma Repository

- Mock Repository：当前默认启用，读取 `seed-v0.3/seed-v0.4` 和内存 Mock Store。
- Prisma Repository：当前只保留骨架和 TODO，占位方法会抛出清晰错误，不会默认连接数据库。

## DATA_SOURCE 切换规则

`apps/api/.env.example` 预留：

```env
DATA_SOURCE=mock
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public
```

- `DATA_SOURCE=mock`：使用 Mock Repository，当前默认。
- `DATA_SOURCE=prisma`：未来启用 Prisma Repository。
- 如果 `DATA_SOURCE=prisma` 但 `DATABASE_URL` 为空或仍是示例值，后端启动会报出清晰错误。

## 后续接 Sealos 步骤

1. 准备 Sealos PostgreSQL 测试库。
2. 配置真实 `DATABASE_URL`，先只在本地测试环境启用。
3. 将 Prisma Repository 的占位方法替换为真实查询。
4. 将 `seed-v0.4.ts` 转换为 Prisma seed。
5. 先在测试库执行 migrate，并验证 API 和前端。
6. 备份生产数据后，再制定生产迁移窗口。
