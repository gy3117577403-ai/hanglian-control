# V0.6 资料版本管理与迁移准备

## 阶段目标

V0.6 在保持 `DATA_SOURCE=mock` 的前提下，实现资料版本管理、上传/变更审计记录、迁移预览和 Prisma seed JSON 导出准备。不连接真实 Sealos PostgreSQL，不执行 `prisma migrate`、`prisma db push` 或真实 seed。

## 版本分组规则

同一组资料由以下字段共同确定：

```text
productId + documentType + requiredForProcess
```

例如同一产品的 PDF 图纸、SOP 图片、孔位图可以各自拥有 Rev.A、Rev.B、Rev.C 等多个版本，但每一组最多只有一个 `effective` 当前有效版本。

## 设置当前有效版本规则

- 被设置的资料状态改为 `effective`。
- 同组其他 `effective` 资料自动改为 `expired`。
- 生成 `document_set_effective` 审计记录。
- 重新计算 readiness，并生成 `readiness_recalculated` 审计记录。
- `expired` 资料仍可查看和对比，但不作为当前生产资料。
- `pending_review`、`inconsistent` 会触发复核或阻断提醒。
- 归档只标记 `archived=true` 和 `status=expired`，不物理删除文件。

## 审计记录规则

本地审计记录保存到：

```text
apps/api/storage/metadata/audit-logs.json
```

记录字段包括：

- `auditId`
- `entityType`
- `entityId`
- `action`
- `before`
- `after`
- `message`
- `operatorId`
- `operatorName`
- `operatorRole`
- `planId`
- `productId`
- `createdAt`

当前记录的动作包括资料上传、状态变更、版本变更、设为有效、归档、文件预览、readiness 重算和迁移预览生成。

## 迁移预览说明

`GET /api/migration/preview` 只返回统计，不连接数据库，不写入数据库。

`GET /api/migration/export-seed` 只返回 JSON 结构，供后续 Prisma seed 或导入脚本参考，不包含真实密钥，不写入数据库。

文件本体仍保存在 `apps/api/storage/uploads`，后续接 Sealos 时只建议迁移文件元数据和审计记录，不建议把 PDF/图片二进制写入数据库。

## 当前仍未接 Sealos 的原因

- 真实数据库账号、权限、备份、回滚方案尚未确认。
- 生产资料文件存储策略尚未最终确定。
- 企业微信微盘和对象存储授权未接入。
- 当前阶段只验证版本管理和迁移数据结构，不进行真实持久化切换。
