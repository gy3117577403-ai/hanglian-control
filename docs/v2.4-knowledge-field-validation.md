# V2.4 知识库现场验证与批量维护

## 阶段目标

V2.4 在 V2.3 治具库、异常库、质量标准库的基础上，补齐“开工前现场知识检查”的闭环。系统仍为本地 Mock / metadata 演示版，不连接 Sealos PostgreSQL，不接企业微信微盘，不接真实语音识别，不执行数据库写入。

## 已完成范围

- 新增计划维度知识验证 API：`GET /api/knowledge/plan/:planId/validation`。
- 新增产品维度知识验证 API：`GET /api/knowledge/product/:productId/validation`。
- 新增计划知识推荐 API：`GET /api/knowledge/plan/:planId/recommendations`。
- 新增治具库、异常库、质量标准库批量维护 API。
- 开工资料 readiness 检查联动现场知识验证结果。
- 平板现场知识区拆分为验证、治具、异常、质量标准四个区域。
- 快捷操作增加查看治具、查看异常、查看质量标准、打开知识区、复制摘要。
- 资料维护中心增加知识库批量状态、工序、严重度、缺陷等级维护。
- 复核队列追加知识库阻塞和待复核项。
- 导入预览增强知识库字段校验。
- 新增 `npm run knowledge-validation:check` 只读检查。

## 现场验证规则

治具检查：
- 当前产品 / 工序必须有关联治具。
- 至少存在一个启用状态治具。
- 治具需要填写点检标准。

异常检查：
- 展示当前产品 / 工序相关异常案例。
- high / critical 且未关闭的异常作为班前重点提醒。

质量标准检查：
- 当前产品 / 工序必须有关联质量标准。
- 至少存在一个 effective 状态质量标准。
- pending_review 显示复核提醒，expired 显示红线阻塞。

## 数据边界

当前阶段只使用 Mock seed 与本地 metadata 文件：
- `knowledge-fixtures.json`
- `knowledge-abnormal-cases.json`
- `knowledge-quality-standards.json`
- `knowledge-records.json`

这些 metadata 文件已被 `.gitignore` 忽略，不提交 Git。V2.4 不连接真实数据库，不执行 migrate、db push、seed 或只读数据库连接。
