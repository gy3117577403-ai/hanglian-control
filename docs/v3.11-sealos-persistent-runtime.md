# V3.11 Sealos Persistent Runtime Preparation

V3.11 prepares the project for a split Sealos deployment without connecting to the real database or object storage.

## Scope

- API and Tablet are prepared as two separate container images.
- API runtime defaults to Mock data and local file storage.
- API local storage is aligned to the future Sealos persistent volume path: `/data/hanglian`.
- Tablet reads API endpoint settings at container runtime from `runtime-config.js`.
- CORS is controlled by an explicit allowlist.
- Cloud startup has safety gates for Prisma migration.
- GitHub Actions image build is manual only.

## What remains paused

- Sealos PostgreSQL connection.
- Prisma migrate, db push, db seed, and test-db seed.
- Real S3/Object Storage connection.
- WeCom Drive integration.
- Real voice recognition.
- Sealos app deployment or modification.

## API container

The API container uses `Dockerfile.api`.

Default safe runtime:

```env
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
API_PREFIX=api
DATA_SOURCE=mock
DEMO_DATA_MODE=empty
FILE_STORAGE_PROVIDER=local
STORAGE_ROOT=/data/hanglian
METADATA_ROOT=/data/hanglian/metadata
STORAGE_TEMP_ROOT=/data/hanglian/tmp
RUN_PRISMA_MIGRATE_DEPLOY=false
ALLOW_TEST_DB_CONNECT=false
ALLOW_PRISMA_WRITE=false
ALLOW_DESTRUCTIVE_DB_ACTIONS=false
```

Health endpoints:

- `GET /api/health`
- `GET /api/runtime/info`
- `GET /api/storage/status`
- `GET /api/storage/mount-readiness`

The endpoints expose safe status only. They must not expose `DATABASE_URL`, database passwords, S3 keys, tokens, or local absolute secrets.

## Tablet container

The Tablet container uses `Dockerfile.tablet`.

It serves the built PWA through Nginx and writes `runtime-config.js` on container startup from these runtime environment variables:

```env
RUNTIME_API_BASE_URL=https://YOUR_API_DOMAIN/api
RUNTIME_APP_ENV=sealos-demo
RUNTIME_STORAGE_MODE=persistent-volume
```

`runtime-config.js`, `index.html`, and service worker files are configured as no-cache resources so the tablet can pick up endpoint changes after redeploy.

## Persistent volume plan

Mount a Sealos persistent volume to the API app only:

```text
/data/hanglian
```

The API stores runtime files below:

```text
/data/hanglian/uploads
/data/hanglian/metadata
/data/hanglian/tmp
```

For the current file-based metadata mode, keep API replicas at `1`. Multiple replicas can conflict unless file metadata is moved to PostgreSQL or another coordinated backend.

## CORS plan

Set API CORS origins to the deployed Tablet domain:

```env
CORS_ORIGINS=https://YOUR_TABLET_DOMAIN
CORS_ALLOW_CREDENTIALS=false
```

Do not put database URLs, object storage keys, or any secret values in `CORS_ORIGINS`.

## Manual image workflow

The workflow `.github/workflows/build-images-manual.yml` is manual only. It can build and push:

- `ghcr.io/gy3117577403-ai/hanglian-control-api:<tag>`
- `ghcr.io/gy3117577403-ai/hanglian-control-tablet:<tag>`

It does not deploy Sealos, run migrations, seed data, or connect to real services.

```bash

npx prisma migrate dev
npx prisma migrate deploy
npx prisma db push
npx prisma db seed
npm run prisma:seed:test-db -w api
```
