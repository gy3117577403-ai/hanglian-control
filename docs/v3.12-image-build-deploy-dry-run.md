# V3.12 Image Build Validation And Deployment Dry Run

V3.12 validates cloud image build configuration and prepares manual Sealos deployment parameters. It does not deploy anything to Sealos.

## Why this stage exists

The project is moving toward API and Tablet split deployment. Before touching Sealos apps, this stage makes the build outputs repeatable:

- API image and Tablet image are built separately.
- Image tags are immutable and tied to the commit SHA.
- Deployment parameters are documented for manual review.
- Runtime env placeholders are kept separate from real secrets.

## Branch trigger

The workflow `.github/workflows/build-images-manual.yml` keeps `workflow_dispatch` and adds a limited push trigger for:

```text
feature/v3-12-image-build-validation
```

It must not trigger for all `feature/**` branches.

## Images

- API: `ghcr.io/gy3117577403-ai/hanglian-control-api`
- Tablet: `ghcr.io/gy3117577403-ai/hanglian-control-tablet`

Required tags:

- `v3.12-<short-sha>`
- `sha-<short-sha>`

Optional candidate tag:

- `v3.12-candidate`

Forbidden tags:

- `latest`
- `production`
- `stable`

## Preflight checks in GitHub Actions

Before image build, the workflow runs:

```bash
npm ci
npm run security:check
npm run storage-flow:check
npm run cloud-alignment:check
npm run cloud:runtime-preflight
npm run runtime-config:check
npm run build
npm run check
```

If any check fails, images are not built or pushed.

## What the workflow must not do

- It must not deploy to Sealos.
- It must not call Sealos APIs.
- It must not connect to PostgreSQL.
- It must not run Prisma migration, db push, or seed.
- It must not connect to S3.
- It must not read or print `DATABASE_URL`.
- It must not read or print S3 credentials.
